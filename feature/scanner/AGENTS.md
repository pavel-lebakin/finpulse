# :feature:scanner

Package `com.lebakin.finpulse.feature.scanner`. Modules `:feature:scanner:api` and `:feature:scanner:impl`. Group `com.lebakin.finpulse.feature.scanner`.

`api` exposes `ScannerEntry`. It depends on `:core:common`. `openCapture` pushes the capture screen. The app frame opens that screen by replacing the back stack.

`impl` reads a receipt from the camera or the gallery. The capture screen does not list bundled samples. Samples stay available to the parser tests: they skip recognition and go straight to the rule-based parser. The same sample text always produces the same draft. Camera and gallery text go through `ReceiptEngines`. The on-device model is asked for every receipt the prompt accepts. The rule draft is kept when it lists at least as many items as the model. A model reply with more items replaces it. `openByokModel` runs only when both are missing. An accepted reply can include item lines. A missing model, `OnDeviceFailed`, or `ReceiptCheck.Rejected` falls through. A missing consent or key does not call the network. `NoConnectionException` and `ServerStatusException` from BYOK propagate. `CancellationException` is rethrown. An invalid reply is not a transaction: the capture screen shows that the receipt could not be read. A printed currency symbol or code wins. Otherwise Russian text hints RUB, Portuguese, Spanish, French, German, Italian, Polish, and Turkish hint EUR, and English hints GBP when the text says pound or GBP and USD otherwise. The review screen lists each item, the total, and USD, EUR, GBP, and RUB. The chosen code is what Confirm saves. `Confirm` writes one user category and one expense for that total through `LedgerWriter`, and stores the item lines on that expense. A later scan replaces the draft the review screen is showing. Nothing is written from recognition text or model text alone. The prompt, the reply, and the key are not logged. iOS reads image bytes with Vision, with accurate recognition, language correction off, automatic language detection, and words on one row joined so a price stays with its item. Android opens the ML Kit document scanner for the camera, which crops and cleans the page on device, and falls back to a full-size camera file when that scanner cannot start. Gallery images stay full size. A short image is scaled up before recognition. ML Kit lines are grouped into rows by their boxes so a price stays with its item. `text-recognition` 16.0.1, `play-services-mlkit-document-scanner` 16.0.0, and the Play Services artifacts they pull are reviewed Licensee exceptions. The image stays in memory for the read and is not sent by our code.

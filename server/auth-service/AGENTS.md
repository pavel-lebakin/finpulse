# :auth-service

Separate Gradle build `server/`. Package `com.lebakin.finpulse.server.auth`. Not a module of the mobile project.

`Application.auth(accounts, redis)` answers `POST /sessions`. `signIn` returns `SignIn.Accepted` only when the email matches one supplied account and the password matches its `PasswordVerifier`. The verifier is PBKDF2-HMAC-SHA256 with 600000 iterations, a 16-byte salt, and a 32-byte hash. `passwordVerifier` builds it and clears the password array. Any other body is `SignIn.Rejected`. The email and the password are printable ASCII without spaces, quotes, or backslashes, and the password is 8 to 128 characters. When `redis` is passed and the password matches, the route calls `issueSession` and `saveFamily`, then returns 200 and `familyId.tokenHex` with `Cache-Control: private, no-store`. `issueSession` returns a `Session` with a 32-hex-character family id, a 32-byte refresh token, and a hash family. The id is not derived from the token. The text omits the email, the password, the account id, and the hash. Any other call returns 401 with an empty body and the same cache header. `main` binds `127.0.0.1:8081`, calls `auth(emptyList())`, and does not open Redis, so the process issues no session. The password, the email, the salt, the hash, and the token are omitted from `toString` and from exception text. The process does not call PostgreSQL, does not store an account, and does not call `:api-gateway`. `finpulse.cloud.enabled` stays false.

`refreshToken` returns 32 random bytes. `refreshFamily` stores only the SHA-256 of that token. `rotate` returns `Refresh.Rotated` when the hash matches the current token, keeps the same family id, remembers at most 8 previous hashes, and returns a new token. A remembered token returns `Refresh.Reused` and revokes the family. Anything else is `Refresh.Rejected`. `rotate` clears the presented array. The token and the hashes are omitted from `toString` and from exception text. `POST /sessions` does not call `rotate` or `loadFamily`. `main` does not create a family. `saveFamily` writes that family to Redis under `refresh:` plus the family id. The value is version `1`, the ids, the revoked flag, and the hex hashes, not the token. `loadFamily` returns the family, null when the key is missing, and rejects any other value with a fixed message. The test starts `redis-server` on `127.0.0.1`. `FINPULSE_REDIS` selects that executable when it is not on `PATH`.

Check: `scripts/check.sh -p server :auth-service:test :auth-service:detekt :auth-service:licensee`.

### `core/ai/AGENTS.md`

# :core:ai

Package `com.lebakin.finpulse.core.ai`. Depends on `:core:network`, `:core:security`, `:core:preferences`, kotlinx datetime, kotlinx serialization, and, on Android, ML Kit `genai-prompt` 1.0.0-beta5. No feature dependency.

Public types: `ReceiptReply`, `ReceiptCategory`, `ReceiptCheck`, `receiptPrompt`, `checkReceiptReply`, `OnDeviceModel`, `OnDeviceFailed`, `openOnDeviceModel`, `OnDeviceEngine`, `registerOnDeviceEngine`, `ByokModel`, `ByokFailed`, `openByokModel`.

`receiptPrompt` places receipt text between `RECEIPT_DATA_BEGIN` and `RECEIPT_DATA_END`. Those markers inside the text are broken so the block has one end. The instructions do not tell the model to follow commands from the receipt. `checkReceiptReply` accepts one JSON object with `merchant`, `amountMinor`, `currencyCode`, `occurredOn`, and `categoryName`. `amountMinor` is a positive integer of at most nine digits. A repeated key is rejected. Anything else is `ReceiptCheck.Rejected`. An accepted value is a `ReceiptReply`, not a transaction.

`openByokModel` returns a `ByokModel` only when `ConsentPreferences.isGranted` is true and `SecretStore.read` yields one printable ASCII key of at most 512 characters. Missing consent, a missing key, a blank key, or a key with whitespace returns null and does not call the network. `complete` reads consent and the key again and posts the prompt to `https://generativelanguage.googleapis.com/v1beta/models/gemini-3.8-flash:generateContent`. The key travels only in the `x-goog-api-key` header. It is not placed in the URL, the JSON body, or an exception message. The prompt is a JSON string. The reply text is the first candidate's non-thought parts. Empty, non-JSON, or text-less replies throw `ByokFailed` and are not a transaction. A revoked consent throws `ByokFailed` before the next post. `NoConnectionException`, `ServerStatusException`, and `CancellationException` propagate. The prompt, the reply, and the key are not logged. `openByokModel` is hidden from Swift. The model is not bound in Koin. `:feature:scanner` calls it only after the rule-based parser cannot read the receipt. This step does not save a key.

`openOnDeviceModel` returns an `OnDeviceModel` only when that platform has a ready engine. Android returns one when ML Kit reports `FeatureStatus.AVAILABLE` for Gemini Nano. A downloadable or missing engine returns null, and this step does not start a download. iOS returns one only after Swift calls `registerOnDeviceEngine` and `OnDeviceEngine.ready` is true. Apple Foundation Models stay in Swift. A missing registration, an older system, or an unavailable Apple Intelligence model returns null, and this step does not start a download. The JVM returns null. `complete` returns the model text. An empty reply or a model failure is `OnDeviceFailed` and is not a transaction. `CancellationException` is rethrown. The prompt and the reply are not logged. `genai-prompt` 1.0.0-beta5, `genai-common` 1.0.0-beta5, `genai-schema` 1.0.0-alpha2, `play-services-basement` 18.9.0, and `reactive-streams` 1.0.3 are reviewed Licensee exceptions. `:feature:scanner` calls this before the rule-based parser. The model is not bound in Koin. `registeredOnDeviceEngine` is hidden from Swift and is what the iOS platform module binds.

Check: `scripts/check.sh :core:ai:jvmTest :core:ai:compileKotlinIosSimulatorArm64 :core:ai:detekt :core:ai:licensee`.

### `feature/scanner/AGENTS.md`

# :feature:scanner

Package `com.lebakin.finpulse.feature.scanner`. Modules `:feature:scanner:api` and `:feature:scanner:impl`. Group `com.lebakin.finpulse.feature.scanner`.

`api` exposes `ScannerEntry`. It depends on `:core:common`. `openCapture` pushes the capture screen.

`impl` reads a receipt from the camera, the gallery, or a bundled sample. Samples skip recognition and go straight to the rule-based parser. The same sample text always produces the same draft. Camera and gallery text go through `ReceiptEngines`. A ready on-device model is tried first. An accepted reply becomes the draft. A missing model, `OnDeviceFailed`, or `ReceiptCheck.Rejected` falls through to the rule-based parser. That parser is used when it can read the text, and then BYOK is not opened. When the rules cannot read the text, `openByokModel` is tried. An accepted reply becomes the draft. A missing consent or key does not call the network. `NoConnectionException` and `ServerStatusException` from BYOK propagate. `CancellationException` is rethrown. An invalid reply is not a transaction: the review screen shows the rule draft, or the capture screen shows that the receipt could not be read. `Confirm` writes one user category and one expense through `LedgerWriter`. Nothing is written from recognition text or model text alone. The prompt, the reply, and the key are not logged. iOS reads image bytes with Vision. Android reads Latin text with ML Kit `text-recognition` 16.0.1. That artifact and the Play Services libraries it pulls are a reviewed Licensee exception. The image stays in memory for the read.

# iosApp

Xcode project `iosApp/iosApp.xcodeproj`, bundle id `com.lebakin.finpulse`, iOS 16. Signing is off.

Startup: `registerFoundationOnDeviceEngine()`, then `KoinKt.doInitKoin()`, then `MainViewControllerKt.MainViewController()`. On iOS 26 and later that registration passes Apple Foundation Models through `OnDeviceEngine`. An unavailable model stays unready, and the app does not download it. The prompt and the reply are not logged. The framework is looked up in `shared/build/xcode-frameworks`. Camera and photo library usage strings are in `Info.plist`. The photo stays on the device. App Transport Security sets `NSAllowsArbitraryLoads` to false, so cleartext is off.

The simulator build command is in `finpulse-workflow/references/build.md`. Do not run it on every commit.

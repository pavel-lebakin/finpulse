### `core/mvi/AGENTS.md`

# :core:mvi

Package `com.lebakin.finpulse.core.mvi`. Depends on `:core:common`.

Public types: `ScreenState`, `ScreenAction`, `ScreenViewModel`. State changes only through `reduce { }`. `launchCatching` maps an error to `AppError` and does not swallow `CancellationException`.

### `core/navigation/AGENTS.md`

# :core:navigation

Package `com.lebakin.finpulse.core.navigation`. Depends on `navigation3-ui` as `api`.

Public types: `Destination` (`NavKey`), `RootNavigator`, `RootCommand` (`Open`, `Replace`, `Back`), `ComposeRootNavigator`. `replace` swaps the back stack for one destination so a finished flow is not left underneath.

Commands queue until `attach` is called and are cleared on `detach`. A feature calls only `RootNavigator`. `NavDisplay` lives in `:shared`.

Check: `scripts/check.sh :core:navigation:jvmTest :core:navigation:compileKotlinIosSimulatorArm64`.

### `feature/ledger/AGENTS.md`

# :feature:ledger

Package `com.lebakin.finpulse.feature.ledger`. Modules `:feature:ledger:api` and `:feature:ledger:impl`. Group `com.lebakin.finpulse.feature.ledger`.

`api` exposes `Transaction`, `Category`, `MoneyDirection`, `RecordOrigin`, `LedgerReader`, and `LedgerWriter`. It depends on `:core:common` and kotlinx.

`impl` stores rows through `:core:database` and the showcase flag through `:core:preferences`. `ShowcaseHistory` builds three months of rows with `origin = SHOWCASE`. `addUserTransaction` deletes every showcase row and inserts the user row in one Room transaction, then turns showcase mode off. `clearShowcase` deletes the sample and does not insert a row. Seeding does nothing when a user row already exists.

No screen and no network. Platform file paths stay in `core`.

Check: `scripts/check.sh :feature:ledger:api:jvmTest :feature:ledger:impl:jvmTest :feature:ledger:api:compileKotlinIosSimulatorArm64 :feature:ledger:impl:compileKotlinIosSimulatorArm64 :feature:ledger:api:detekt :feature:ledger:impl:detekt`.

### `feature/onboarding/AGENTS.md`

# :feature:onboarding

Package `com.lebakin.finpulse.feature.onboarding`. Modules `:feature:onboarding:api` and `:feature:onboarding:impl`. Group `com.lebakin.finpulse.feature.onboarding`.

`api` exposes `OnboardingChoice`, `OnboardingReader`, `OnboardingWriter`, and `OnboardingEntry`. It depends on `:core:common` and kotlinx.

`impl` draws one flow of four promises, then a home screen. `complete(Sample)` seeds the showcase ledger. `complete(Empty)` clears showcase rows and leaves an empty hint. Home shows the sample banner and Clear now while showcase mode is on. `OnboardingEntry.showAgain` clears the completed flag and opens the four promises again. Settings does not exist yet, so Home is the caller. No network.

Check: `scripts/check.sh :feature:onboarding:api:jvmTest :feature:onboarding:impl:jvmTest :feature:onboarding:api:compileKotlinIosSimulatorArm64 :feature:onboarding:impl:compileKotlinIosSimulatorArm64 :feature:onboarding:api:detekt :feature:onboarding:impl:detekt`.

### `tooling/architecture-tests/AGENTS.md`

# :tooling:architecture-tests

JVM module. Package `com.lebakin.finpulse.tooling.architecture`. It is not part of the app. Konsist reads the repository sources.

Production rules:

- Extensions of `object *Reducer` on a `*State` type are called only from `reduce {}`. `initial()` stays in `createInitialState()`.
- `Loadable` is the only sealed interface with that name, not a value class.
- `*Dto` and `*Entity` are declared and imported in a package with a `data` segment or in `com.lebakin.finpulse.core.database`.

Check: `scripts/check.sh :tooling:architecture-tests:test :tooling:architecture-tests:detekt`.
